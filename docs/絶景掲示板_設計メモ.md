# 絶景掲示板 設計メモ

沿線だけでなく銚子エリア全体の絶景スポットを扱う、もう一つの掲示板的ウェブサイト。パソコン専用・横構図。
既存の「車窓絶景ナビ」（[設計書.md](設計書.md)、銚子電鉄沿線限定）とは別画面として作る。応募作品の一部。

本体は `board.html`（2026-08-19 に実装）。ローカルサーバー越しに開けば触って確かめられる。

**`board.html` は生成物なので直接編集しない。** 直すのは
[tools/board-template.html](../tools/board-template.html) のほうで、直したら
`node tools/build-board.js` で作り直す。作り直し忘れは
`node tools/check-board-fresh.js`（pre-commitフックとGitHub Actionsからも走る）が拾う。
手順は [README「絶景掲示板を作り直す」](../README.md#絶景掲示板を作り直す) を参照。

比較用に置いていたプロトタイプ（`ai/artifacts/絶景掲示板/mockups/board-map-variant-v4.html`）は、
本体ができたので削除した。決定の経緯を記した mockup-decision の各文書はそのまま残してある。

なぜ立体の地図にしたか（車窓絶景ナビは平面のイラストという既存方針の例外にあたる）は
[ADR-0005](adr/0005-絶景掲示板だけは斜め視点の立体地図にする.md) に記録した。
線路の高さ表現を5案から選んだ経緯の詳細は
[ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md](../ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md) を参照。

## 1. 全体の機能（実装済み）

- 目的: 旅行前にどこにどんな絶景スポットがあるかを知らせる。
- 一番大事な画面: 斜め視点の2D地図。地図上にピンを刺し、タップすると右側にその場所の写真パネルが出る
  （コメント形式）。
- **投稿（写真）: 開けている**（2026-08-19 に方針を変更。[ADR-0004 の追記](adr/0004-投稿と集計のためにサーバーを持ち、ログインは持たない.md)）。
  入口は二つある。
  - **旅の記録から**（`index.html`、スマートフォン）。その日撮った写真の一覧から出すものを選び、
    同意 4 点に印を付けて送る。掲示先は**撮ったときの絶景スポット**から自動で決まる。
    成因カードや撮影の直後には出さない——入口はここだけにする。
  - **掲示板の投稿の窓から**（`board.html`、パソコン）。撮った場所の記録が無い写真のための口。
    地図をクリックするとピンが出て、ずらして場所を決める（現在地から始めることもできる）。
  どちらも **EXIF（撮影地点・端末・撮影時刻）は送る前に端末側で落とす**。長辺 1600px に縮める。
  処理は `js/photo-post.js` にまとめてあり、二つの入口で共有している。
- **審査を通るまで掲示されない。** 送られた写真はサーバーの中に入り、誰にも読めない。
  制作者が `review.html`（合言葉で開く）で目で見て通し、`node tools/publish-posts.js` を
  走らせて `assets/choshi/board/posts/` へ置き、commit して push した時点で掲示される。
  **公開されているのはリポジトリのファイルのほうで、サーバーではない。**
- **投稿例（見本）のカードは削除した。** 本物の投稿を受け付けるようになった以上、
  「投稿するとこう見える」の見本を置く理由が無くなったため。
- **掲示板に出るのは写真だけ。文字は送らない**（2026-08-19 の決定）。乗客が書いたひとこと・
  結びの一文は、端末と旅の記録の中だけに残る。文字を送る仕組み（ADR-0004 の `submit_notes`）は
  消していないので、戻すときは画面につなぎ直せばよい。
- ピン配置: 地図上の任意の位置に自由に落とす。ほぼ同じ座標のスポットは1本のピンにまとめる
  （外川漁港・きんめだいなど）。**まとめていることを示す件数バッジは出さない**——地図上は
  普通の1本のピンに見え、開くと同じ場所の写真が複数並ぶ（2026-08-19。バッジ表示だけをやめ、
  まとめる仕組み自体は元に戻した）。
- 画像利用: 銚子市観光協会フォトダウンロードの許諾条件に従う
  （[docs/銚子市観光協会フォトダウンロード利用規約.md](銚子市観光協会フォトダウンロード利用規約.md)参照。
  直リンク禁止、ローカル保存、クレジット表記必須、商用不可）。
- データ保持: 投稿は ADR-0004 の削除タイミング（2027-04-30 一括削除）に合わせる。
- 累積人気: 「いいね」は累積人気と同じ仕組み（IPハッシュ、`record_board_like`）で**本物を数える**。見本の固定値（`sampleLikes`）は 2026-08-19 に廃止した。
- 導線: 車窓絶景ナビの乗車区間の画面（`index.html` の最初に出る札）の下に「銚子の絶景を地図で眺める（絶景掲示板）」を置いた。あちらは旅行**前**の画面なので、乗る前に渡す。
- モバイル: 画面幅 760px 以下では地図を出さず、案内ページのみを表示する（PC専用機能のため）。文面は 5 章。**実装済み**（Playwright で確認）。
- GPS: ユーザーのGPSを読み取り、位置入力の補助として使う。

## 2. 掲示スポット（公式写真 12 件＋車窓絶景ナビと同じ場所 4 件）

`掲示website/掲示写真` にある12枚すべてを、実在の場所に対応づけて使う。

これに加えて、**車窓絶景ナビの絶景スポットと同じ場所を指す 4 件**（S01 ヤマサ醤油工場・
S02 遠くに見える海・S03 森のトンネル・S05 ひまわり畑）を掲示スポットとして持つ
（2026-08-19 追加、合計 16 件）。観光協会の公式写真は無く、**乗客から届いた写真が
1 枚も無いあいだは地図にピンが出ない**。座標は `data/choshi/spots.json` の実データを
そのまま使うので、作り話の座標は増えていない。S04 キャベツ畑と S06 河津桜・菜の花は、
既にある `cabbage`・`togawaeki` と座標が一致するので、そちらに `naviSpotId` を書いて
相乗りさせている。

**座標の出どころ**: 2026-08-19 に、無償で使える地図データだけで座標を洗い直した。
出典・確からしさは [data/choshi/board-spots.json](../data/choshi/board-spots.json)
（人が手で書くファイル）に1件ずつ記録してある。使ったのは次の3つ、いずれも無償・出典表示のみで使える。

- **OpenStreetMap**（ODbL ライセンス）— 灯台・岩・展望台など、地物として登録されている9件
- **国土地理院 地名検索**（政府の公式データ）— 町丁目までしか特定できなかった2件（外川漁港の付近、松岸）
- **この作品が既に持っている実データ** — 外川駅・キャベツ畑は、車窓絶景ナビ側の
  `route.json`・`spots.json` の値をそのまま使う（同じ場所を指すので座標を揃えた）

洗い直しで分かったこと: プロトタイプに仮置きしていた座標のうち **4件（地球の丸く見える丘展望館・
屏風ヶ浦・千騎ヶ岩・犬岩）は、実際の位置と1〜4km ずれていた**（出どころの記録がなく、目分量だった
とみられる）。この4件は新しい座標に直した。外川駅・キャベツ畑は元から正確だった（既存の実データを
借用していたため）。

## 3. 地図画面の仕様（board.html で実装した内容）

画面の要素ごとに、現状の実装と未決を分けて書く。実装のたびにここを更新すること。

| 要素 | 内容 |
|---|---|
| 背景 | 実データの地形（国土地理院DEMから取得した等高線バンド、0/8/16/24/32/45m）。段彩配色は設計書5.2と共通。 |
| 表現形式 | CSSの3D変形（`perspective`＋`rotateX`＋`rotateZ`）で斜め視点。理由はADR-0005。 |
| 地形の誇張度 | 標高 × 1.2倍（×2.4を試して「浮いて見える」の指摘で調整）。 |
| 操作 | ドラッグで移動、Ctrl+ドラッグ（または右ドラッグ）で回転・傾き、ホイールで拡大縮小。ズーム0.5〜4倍、傾き15°〜70°。コンパスクリックで**初期表示（角度・拡大度・位置すべて）**にリセット。 |
| 初期表示 | heading 0°・tilt 35°・zoom 2.7（北が上。ユーザーからの参考スクリーンショットにPlaywrightで近づけて決定。経緯は[mockup-decision-初期角度.md](../ai/artifacts/絶景掲示板/mockup-decision-初期角度.md)）。 |
| 線路の立体表現 | **5案から選んだ「駅を通る曲線・白い縁なし」に固定**（2026-08-19、比較用の切替パネルは削除）。 |
| ピン | 四角い写真（58×42px）＋三角の尻尾。**ほぼ同じ座標のスポットは1本にまとまるが、件数バッジは出さない**（2026-08-19。開くとパネルに複数枚並ぶ）。**ピンは3Dの世界の中には置かず、地図の上に重ねた平らな層に並べる**（`.pins-overlay`）。位置は3D座標を JS で画面に投影して決めるので（`projectToScreen`）、**高さは各スポットの実測標高そのまま**——尻尾の先がその場所の地面にちょうど触れる。地形の色分けが45m以上をひとまとめにしている都合で、高さは45mで頭打ち。**画面のどこが中心かは JS で計算せず CSS の `left/top: 50%` に任せる**（写真パネルが開く0.45秒のあいだピンだけ取り残される不具合の対策。[ADR-0005](adr/0005-絶景掲示板だけは斜め視点の立体地図にする.md)）。 |
| 写真パネル | 初期は非表示。ピンタップで地図が縮小しながら右からスライドイン。何もない場所のタップ、または **Esc キー**で閉じる。公式（観光協会提供）と乗客から届いた写真の別はカード内バッジで示す（地図上のピンでは示さない）。**乗客の写真には文字が付かない**（1章）。閉じると、開いたピンにフォーカスが戻る。 |
| 位置が概略のスポット | `confidence: "approximate"` の4件（外川漁港・きんめだい・銚子電鉄とキャベツ畑・銚子ちぢみ）は、写真パネルに「この場所の位置はおおよそです（現地で確かめる予定）」と小さく添える。ピンの見た目は変えない。 |
| 駅名ラベル | 背景の四角は置かず、白い縁取り（`text-stroke`）だけで視認性を確保。**ピンと同じく3Dの世界の外に置き、位置は `projectToScreen` で投影して決める**（2026-08-20。それまではビルボード方式で3Dの中にあり、角度によって地形の板の裏に回って文字が欠けた）。おかげで**どの画角に回しても、駅名は地形と線路の上に出る**。書体・字の大きさ・拡大に応じた伸縮は移す前と同じ（11駅ぶんを実測して最大0.1pxの差）。ピンより下（z-index 3）に置くので、写真のピンが手前に来る重なり順は変わらない。 |
| 線路の高さ | 駅を通る曲線（Catmull-Romスプライン）。ハローなし。5案の比較はmockup-decision参照。 |
| 路線外区間 | 銚子〜松岸（JR）は点線で表示。 |
| トップバー | 左に画面名、右に操作の説明（ドラッグ／ホイール／Ctrl+ドラッグ）。説明はもともと地図の左上に浮かせていたが、そこは松岸（銚子ちぢみ）のピンが来る場所なので上バーへ移した（2026-08-19）。地図の上には地図と最小限の操作UIだけを載せる。 |
| 投稿ボタン（FAB） | 右上の丸ボタン「＋投稿する」。クリックで投稿の窓を開く。宛先（`js/popularity.js`）が読めていないときは**ボタンごと出さない**（設計書9.3）。 |
| 投稿の窓 | 写真を選ぶ欄、場所（地図をクリックしてピンを置く／現在地ボタン／矢印キーで微調整）、同意チェック4点（自分で撮影／他者の顔が写っていない／16歳未満は保護者同意／2027-04-30に全削除されることの理解）、「審査に送る」ボタン。**本当に送れる**（`js/photo-post.js` → `submit_photo`）。ひとこと欄は置かない——掲示板に出るのは写真だけだから（1章）。`role="dialog"` だが **`aria-modal` は付けない**（背後の地図をクリックして場所を決めるため。6章）。 |
| いいね | ひし形アイコン。押すと `record_board_like` を呼び、**本物の数**が増える（IPハッシュで一人一日一票、001の累積人気と同じ数え方）。数が取れなかったときは**ボタンごと出さない**。公式写真は掲示スポットの id、乗客の写真は投稿の id で数える。 |
| コンパス・縮尺 | 左下に方位針とスケールバー（2km）。方位針は**「初期表示に戻す」ボタン**を兼ねる（`<button>`。キーボードでも押せる）。 |
| 凡例 | 右下に点線区間・提供元の注記。 |

## 4. なぜそう決めたか

- **CSS 3D の斜め視点にした理由**: ADR-0005 を参照。車窓絶景ナビ（ADR-0001）は「車内で一瞬見る」ための平面イラストだが、絶景掲示板はPCでじっくり眺める別の画面のため、例外として立体にした。
- **地形の誇張度 ×1.2**: 最初 ×2.4 を試したが「あらゆるものが浮いて見える」との指摘を受けて控えめに調整した。
- **線路の高さ表現**: 5案（階段状／実測を軽く均す／しっかり均す／駅を通る曲線／平坦＋支柱）を作って比較し、駅を通る曲線を採用。理由と比較表は [mockup-decision-線路の高さ表現.md](../ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md)。
- **線路の縁取り（白いハロー）はなし**: 比較のうえ「圧倒的にこちらが良い」との判断による。
- **ピンは3Dの外に出し、投影して置く**: 「地図に対して浮いて見える」というFB（2026-08-19）を受けて二段階で直した。まず、常に最高標高に固定する方式から各スポットの実測標高を使う方式に変えた。しかしCSSの3D表現は板を重ねているだけで本物のZバッファ計算ではないため、地形のいちばん上の板（z=54）より高く持ち上げないと低地のピンが裏に回って消える。そのため底上げ +80 を入れており、地形全体の高さが54しかない以上これは「地形の1.5倍の高さに浮かせる」ことだった（**「すごく浮いている」という2回目のFBの原因はここ**）。

  そこで、ピンを3Dの世界から出し、3D座標をJSで画面座標に投影して平らな層に並べる形に変えた。前後関係の問題そのものが無くなるので底上げが要らなくなり、ピンは地面の高さに置ける。代償は、`.map-wrap` の `perspective` と `.camera-rig` の変形と同じ計算をJS側にも持つこと（片方を変えたらもう片方も直す）。詳細と検証結果は [ADR-0005](adr/0005-絶景掲示板だけは斜め視点の立体地図にする.md)。
- **駅名も3Dの外へ出した**（2026-08-20）: 「地形と駅名が重なって読みにくい。どの画角に回しても
  文字は線路の上にあってほしい。フォントや大きさは変えないで」というFBを受けた。原因はピンの
  ときと同じZバッファの無さで、駅名だけは3Dの中に残っていたため、角度によって地形の板の裏へ
  回り、松岸・観音・本銚子のように台地の縁にかかる駅名が半分欠けていた。ピンと同じ平らな層
  （`.stations-overlay`）へ移し、位置は `projectToScreen` で毎フレーム求める形にした。
  **書体・字の大きさは変えていない**——旧実装と新実装で11駅ぶんの画面上の位置・幅・書体・
  字の大きさを実測して比べ、初期表示でも回転・傾き・拡大を加えた状態でも差は最大0.1pxだった。
  ピンより下（z-index 3）に置いてあるので、写真のピンのほうが手前という重なり順は変わらない。
  正面を向け直すビルボードの仕組み（`refreshBillboards`）は、平らな層では不要になるので削除した。
- **件数バッジは出さないが、まとめる仕組みは残す**: 「この『2』はいりません」というFBを受けて、
  一度はまとめる仕組み自体（クラスター化）を丸ごと削除した。しかしこれには副作用があった。
  外川漁港ときんめだいは意図的に同じ座標（きんめだいは場所ではなく特産品なので、水揚げされる
  外川漁港の位置をそのまま使っている）で、まとめる仕組みがないと2枚が完全に重なって見分けが
  つかなくなる。ずらして対応しようとしたが、「同じ座標なのだからまとめてよい。ただしまとめて
  いることをバッジで見せる必要はない」という2回目のFBを受け、**バッジ表示だけをやめ、まとめる
  仕組み（近い座標を1本のピンにする）自体は元どおりにした**。地図上は普通の1本のピンに見え、
  開くと同じ場所の写真が複数並ぶ。
- **地図をクリックして場所を置く仕組み**: `projectToScreen`（世界座標→画面）の逆算
  （`screenToWorld`）で、クリックした点を地面の高さで解き直している（0 で一度解いて
  地形の高さを引き、その高さでもう一度解く）。地形の高さは、段彩の板そのものを
  `Path2D` の当たり判定に使って求める——40MB の標高格子を画面に持ってこなくても、
  描いてある地面の高さは分かる。**往復（投影→逆算）のずれが 0 であることは
  Playwright で確かめた**（3 つの角度・拡大率 × 4 点、2026-08-19）。
  `.map-wrap` の `perspective` と `.camera-rig` の変形を直したら、この逆算も直すこと。
- **写真は丸ではなく四角**: 地図アプリのピンではなく「写真そのものが刺さっている」印象を優先した。

## 6. アクセシビリティ・キーボード操作（実装ずみ・2026-08-19）

- **Esc キーで写真パネル・投稿モーダルを閉じる。** 両方が開いているときは手前のモーダルから閉じる。
  閉じたあとは、開くのに使ったピン（またはFAB）にフォーカスを戻す。
- **ピン・ボタン類にフォーカスリングを表示する。** `:focus-visible` にだけ出すので、マウスで押した
  ときには出ない。ピンだけは `outline` が `preserve-3d` の中で地形の板に隠れることがあるため、
  `.pin-photo` の `box-shadow` に重ねる形で描いている（影と同じ理由。3章の脚注参照）。
- **投稿の窓は、背後を塞がないダイアログにした**（2026-08-19 に変更）。`role="dialog"` +
  `aria-labelledby` は付けるが、**`aria-modal` は付けず、Tab も閉じ込めない**。写真の場所は
  背後の地図をクリックして決めるので、背後を「無いもの」として扱えないためである。幕も
  暗くせず、クリックを地図へ通す。開いたときにフォーカスを中へ移すこと、Esc と「閉じる」で
  FAB へ戻すことは変えていない。
  **クリックで地図を触れない人のために、下書きのピンは矢印キーで動かせる**（Shift で 4 倍）。
  「現在地を使う」を押せば、そこから始められる。
- **同意欄のチェックボックスは `<label>` で包む。** 文字を押しても切り替わるようにするため。
- **ピンは `role="button"` と `aria-label` を持つ。** `div` に `tabindex` を付けただけでは
  押せるものだと伝わらない。名前を `.pin-label` に頼らないのは、あれが普段 `opacity: 0` で
  隠れているため。まとめたピン（外川漁港・きんめだい）は両方の名前を読み上げる。
- **`prefers-reduced-motion` が有効なときは、パネルのスライドイン・地図の縮小を動かさない。**
  `transition: none` にはしていない——パネルの幅の `transitionend` を合図に `fitScale()` を
  呼んでいるので、`none` にすると合図が来ず地図が縮んだままになる。長さをほぼ 0（`.01ms`）に
  することで、見た目は瞬時に切り替わりつつ合図は届く。Playwright で両方の設定で
  `transitionend` が届くことを確認ずみ。パネルを閉じたあと中身を空にするのも、秒数の
  決め打ちではなくこの `transitionend` を合図にしている。

**画面に流し込む文字は必ず `esc()` を通す。** いま入っているのは自分たちで書いた
`board-spots.json` と、写真のファイル名（投稿の id）だけである。乗客が書いた文字は
掲示板には出さないと決めた（1章）ので、当面ここへ他人の書いたものは流れてこない。
それでも外さないのは、外した状態で「やっぱり文字も出す」に戻したときが、いちばん
危ないためである。
