# 絶景掲示板 設計メモ

沿線だけでなく銚子エリア全体の絶景スポットを扱う、もう一つの掲示板的ウェブサイト。パソコン専用・横構図。
既存の「車窓絶景ナビ」（[設計書.md](設計書.md)、銚子電鉄沿線限定）とは別画面として作る。応募作品の一部。

まだ `board.html` の実装には着手していない。地図画面のプロトタイプは
[ai/artifacts/絶景掲示板/mockups/board-map-variant-v4.html](../ai/artifacts/絶景掲示板/mockups/board-map-variant-v4.html)
にあり、ローカルサーバー越しに開けば触って確かめられる（12枚とも実写真、Playwrightで動作確認済み。
2026-08-19）。この文書は、Claude Artifact上での試作とPlaywrightでの動作確認を
重ねて決めた内容の記録。**実装に進む前に必ず参照すること。**

なぜ立体の地図にしたか（車窓絶景ナビは平面のイラストという既存方針の例外にあたる）は
[ADR-0005](adr/0005-絶景掲示板だけは斜め視点の立体地図にする.md) に記録した。
線路の高さ表現を5案から選んだ経緯の詳細は
[ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md](../ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md) を参照。

## 1. 全体の機能（決定済み・実装はこれから）

- 目的: 旅行前にどこにどんな絶景スポットがあるかを知らせる。
- 一番大事な画面: 斜め視点の2D地図。地図上にピンを刺し、タップすると右側にその場所の写真パネルが出る
  （コメント形式）。
- **投稿（写真）: v1（最初に出す形）では、一般の人が写真を投稿する機能は開けない。**
  地図には最初から12枚の公式写真（観光協会提供、2章）に加え、**サンプルとして1〜2件だけ**
  「投稿するとこう見える」という見本の投稿カードを置く（実データではなくダミー、パネル内で
  「投稿例」と分かるように示す）。一般の人が実際に写真を送れるようにするのは、
  **書類審査の結果が出たあと**（2026年10月上旬めやす）に判断する。
  **なぜ**: [ADR-0004](adr/0004-投稿と集計のためにサーバーを持ち、ログインは持たない.md) の
  2026-08-16 追記が「投稿は写真より先に文字から始める。写真を足すときは EXIF 除去と保管場所の設計を
  別に立てること」と決めている。締切（2026-09-09）まで3週間しかない中でこれを新たに作ると、
  投稿を開けたままにする運用（確認当番・pg_cron）の検証が追いつかない。ADR-0004 の順序を守り、
  写真投稿は次の段階に回す。
- **投稿（文字）: 乗客が書いた文字（`public_note`、ADR-0004）は、審査を通ったものに限り
  掲示板でも読めるようにする。** これは新規の投稿口ではなく、ADR-0004 が既に実装している
  ものを初めて画面に出すだけ。応募〜審査結果のあいだも投稿を開けたままにする方針
  （CLAUDE.md「投稿は、応募から審査結果までも開けたままにする」）はこちらの文字投稿にも
  そのまま適用され、写真投稿だけが v1 では止まっている状態になる。
- ピン配置: 地図上の任意の位置に自由に落とす。近いピンは自動でクラスター化し、件数バッジを出す。
- 画像利用: 銚子市観光協会フォトダウンロードの許諾条件に従う
  （[docs/銚子市観光協会フォトダウンロード利用規約.md](銚子市観光協会フォトダウンロード利用規約.md)参照。
  直リンク禁止、ローカル保存、クレジット表記必須、商用不可）。
- データ保持: 投稿は ADR-0004 の削除タイミング（2027-04-30 一括削除）に合わせる。
- 累積人気: 既存の「いいね」の仕組み（IPハッシュ）を流用する。
- 導線: トップページに新規リンク「絶景掲示板」（例: `board.html`）を追加する。
- モバイル: 画面幅が狭いときは地図を閉じ、案内ページのみを表示する（PC専用機能のため）。
  案内ページの文面は 5 章に決定済み。
- GPS: ユーザーのGPSを読み取り、位置入力の補助として使う。

## 2. 最初に載せる12枚の写真と場所（決定済み）

`掲示website/掲示写真` にある12枚すべてを、実在の場所に対応づけて使う。

**座標の出どころ**: 2026-08-19 に、無償で使える地図データだけで座標を洗い直した。
出典・確からしさは [data/choshi/board-spots.json](../data/choshi/board-spots.json)
（人が手で書くファイル）に1件ずつ記録してある。使ったのは次の3つ、いずれも無償・出典表示のみで使える。

- **OpenStreetMap**（ODbL ライセンス）— 灯台・岩・展望台など、地物として登録されている9件
- **国土地理院 地名検索**（政府の公式データ）— 町丁目までしか特定できなかった2件（外川漁港の付近、松岸）
- **この作品が既に持っている実データ** — 外川駅・キャベツ畑は、車窓絶景ナビ側の
  `route.json`・`spots.json` の値をそのまま使う（同じ場所を指すので座標を揃えた）

洗い直しで分かったこと: プロトタイプに仮置きしていた座標のうち **4件（地球の丸く見える丘展望館・
屏風ヶ浦・千騎ヶ岩・犬岩）は、実際の位置と1〜4km ずれていた**（出どころの記録がなく、目分量だった
とみられる）。この4件は新しい座標に直した。外川駅・キャベツ畑は元から正確だった（既存の実データを
借用していたため）。

## 3. 地図画面の仕様（プロトタイプで実装した内容）

画面の要素ごとに、現状の実装と未決を分けて書く。実装のたびにここを更新すること。

| 要素 | 内容 |
|---|---|
| 背景 | 実データの地形（国土地理院DEMから取得した等高線バンド、0/8/16/24/32/45m）。段彩配色は設計書5.2と共通。 |
| 表現形式 | CSSの3D変形（`perspective`＋`rotateX`＋`rotateZ`）で斜め視点。理由はADR-0005。 |
| 地形の誇張度 | 標高 × 1.2倍（×2.4を試して「浮いて見える」の指摘で調整）。 |
| 操作 | ドラッグで移動、Ctrl+ドラッグ（または右ドラッグ）で回転・傾き、ホイールで拡大縮小。ズーム0.5〜4倍、傾き15°〜70°。コンパスクリックで北・傾き52°にリセット。 |
| ピン | 四角い写真（58×42px）＋三角の尻尾。近接ピン（u,v距離0.02未満）は自動クラスター化し、件数バッジを表示。**高さは常に地形の最高点に固定**（標高とは無関係。地形にクリック判定を取られないための割り切り）。 |
| 写真パネル | 初期は非表示。ピンタップで地図が縮小しながら右からスライドイン。何もない場所のタップで閉じる。複数件のクラスターは各カード左上にスポット名。公式／投稿の別はカード内バッジで示す（地図上のピンでは示さない）。 |
| 駅名ラベル | ビルボード方式（回転しても正面を向く）。背景の四角は置かず、白い縁取り（`text-stroke`）だけで視認性を確保。 |
| 線路の高さ | 駅を通る曲線（Catmull-Romスプライン）。ハローなし。5案の比較はmockup-decision参照。 |
| 路線外区間 | 銚子〜松岸（JR）は点線で表示。 |
| トップバー | 画面名のみの単純なバー。 |
| 投稿ボタン（FAB） | 右上の丸ボタン「＋投稿する」。クリックでモーダルを開く。 |
| 投稿モーダル | 写真ドロップゾーン、位置（ピンのドラッグ調整／現在地ボタン）、ひとこと欄、同意チェック4点（自分で撮影／他者の顔が写っていない／16歳未満は保護者同意／2027-04-30に全削除されることの理解）、「審査に送る」ボタン。**v1では実際には送信できない見た目だけの試作**（1章の投稿方針により、写真投稿は次の段階）。 |
| いいね | ひし形アイコン。クリックでON/OFFと件数が変わる。既存の仕組み（IPハッシュ）を流用予定。 |
| コンパス・縮尺 | 左下に方位針とスケールバー（2km）。 |
| 凡例 | 右下にクラスター件数・点線区間・提供元の注記。 |

## 4. なぜそう決めたか

- **CSS 3D の斜め視点にした理由**: ADR-0005 を参照。車窓絶景ナビ（ADR-0001）は「車内で一瞬見る」ための平面イラストだが、絶景掲示板はPCでじっくり眺める別の画面のため、例外として立体にした。
- **地形の誇張度 ×1.2**: 最初 ×2.4 を試したが「あらゆるものが浮いて見える」との指摘を受けて控えめに調整した。
- **線路の高さ表現**: 5案（階段状／実測を軽く均す／しっかり均す／駅を通る曲線／平坦＋支柱）を作って比較し、駅を通る曲線を採用。理由と比較表は [mockup-decision-線路の高さ表現.md](../ai/artifacts/絶景掲示板/mockup-decision-線路の高さ表現.md)。
- **線路の縁取り（白いハロー）はなし**: 比較のうえ「圧倒的にこちらが良い」との判断による。
- **ピンは常に最高標高に固定**: 標高どおりに描くと、低地のピンが台地の板の下に埋もれてクリックできなくなるため。見た目の上下関係はパネル・カードの情報で示す。
- **写真は丸ではなく四角**: 地図アプリのピンではなく「写真そのものが刺さっている」印象を優先した。

## 5. モバイル案内ページ（決定済み・文面）

画面幅が狭いときに地図の代わりに表示する。

> **絶景掲示板は、パソコンでの表示に対応しています**
> この画面は、銚子の絶景スポットをゆっくり眺めていただくための、斜めから見る地図です。
> スマートフォンでは表示できません。パソコンからアクセスしてご覧ください。
>
> 今、電車に乗っていて車窓の絶景を知りたい方は、[車窓絶景ナビ](../index.html) をお使いください。
> スマートフォンでもそのままご利用いただけます。

## 6. アクセシビリティ・キーボード操作（決定済み・実装はこれから）

- Esc キーで写真パネル・投稿モーダルを閉じる。
- ピン・ボタン類にフォーカスリングを表示する（現状のプロトタイプは `outline: none` にしたままなので直すこと）。
- `prefers-reduced-motion` が有効なときは、パネルのスライドイン・地図のズームなどのアニメーションを止める。

## 7. まだ決まっていない・実装はこれから

- 実装そのもの（`board.html`・審査ページ・Supabase連携）は未着手。
- 一般の人による写真投稿を、いつ・どういう形で開けるか（1章のとおり書類審査結果後に判断）。
- 地図の細部（駅名ラベルとピン写真が重なって読みにくい場所がある点など）の詰め。
- 確からしさが「概略」の4件（外川漁港・きんめだい・銚子電鉄とキャベツ畑・銚子ちぢみ、2章）は、
  現地で正確な位置を確認し、`data/choshi/board-spots.json` を直すこと。2026-08-20の現地調査は
  車窓絶景ナビ側（S01〜S06）のためのものでこの4件は対象に入っていないため、別途確認の機会が要る。
