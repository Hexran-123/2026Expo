# 投稿写真の手放し方（2027年4月30日にやること）

乗客から預かった写真は、**2027年4月30日にすべて消す**。これは投稿画面
（`index.html` と `board.html`）に書いてある約束であり、[ADR-0004](adr/0004-投稿と集計のためにサーバーを持ち、ログインは持たない.md)
の決定そのものである。

消す先は**二か所**ある。片方だけでは約束を果たしたことにならない。

| どこ | 何が入っているか | 消し方 |
|---|---|---|
| サーバー（Supabase） | まだ掲示していない写真、投稿の記録 | `purge_expired_photos()`（pg_cron が自動で呼ぶ） |
| リポジトリ（GitHub） | 掲示した写真そのもの | **下の手順**。ファイルを消すだけでは足りない |

## なぜファイルを消すだけでは足りないか

掲示した写真は `assets/choshi/board/posts/` に置き、GitHub Pages から配っている。
`git rm` してもコミットの履歴には残るので、**過去のコミットを開けば誰でも取り出せる**。
「4月30日にすべて削除します」と画面に出しておきながら取り出せる状態は、
[ADR-0004 の追記（2026-08-17）](adr/0004-投稿と集計のためにサーバーを持ち、ログインは持たない.md)
が言う「投稿画面に書いた文言と実際の動作が食い違う状態」にあたる。

個人情報保護法も、利用の必要がなくなった個人データを遅滞なく消去するよう求めており
（22条）、本人からの消去の求めに応じることも求めている（35条）。顔が写りうる写真は
その個人データである。

## 手順（2027年4月30日以降に、一度だけ）

現地展示は 2027年3月17〜19日に終わっているので、この時点で履歴を書き換えて困る人はいない。

```sh
# 0. 念のため、いまの状態をどこかへ控えておく（作業を間違えたときの戻り先）
git clone --mirror . ../2026Expo-backup.git

# 1. 掲示している写真とその表を消す
git rm -r assets/choshi/board/posts
node -e "const fs=require('fs');const p='data/choshi/board-posts.json';const d=JSON.parse(fs.readFileSync(p));d.posts=[];fs.writeFileSync(p,JSON.stringify(d,null,2)+'\n')"
node tools/build-board.js
git add data/choshi/board-posts.json board.html
git commit -m "預かった写真を手放す（2027-04-30、ADR-0004）"

# 2. 履歴からも取り除く（git-filter-repo。pip install git-filter-repo で入る）
git filter-repo --invert-paths --path assets/choshi/board/posts --force

# 3. 書き換えた履歴を push する
git push --force origin master

# 4. GitHub 側に残る古い実体を落とす
#    fork や pull request が無ければ、しばらくで回収される。
#    急ぐなら GitHub のサポートに「force push 前の実体を消してほしい」と伝える。
```
