# フレームワークとサーバーを持たない

> **一部は [ADR-0004](./0004-投稿と集計のためにサーバーを持ち、ログインは持たない.md) で覆された。**
> サーバーとデータベースは、絶景スポットの投稿と累積人気のために持つことにした。
> フレームワーク・ビルド工程・ログインを採用しないことは、そのまま有効である。

制作者 2 名はいずれもウェブ開発の経験がなく、稼働できる日数も限られている。この体制で最も危険なのは、機能の難しさではなく開発環境やビルドの不調で時間を失うことである。そのため React などのフレームワーク、ビルド工程、サーバー、データベース、ログイン機能をいずれも採用せず、素の HTML・CSS・JavaScript のみで構成する。

## Considered Options

React / Next.js を使う案は検討したが、この作品が必要とする画面数と状態は少なく、フレームワークが解決する問題がそもそも発生しない。導入すれば `node_modules` の管理、ビルドエラー、デプロイ設定という、作品の中身と無関係な障害だけが増える。

## Consequences

- ファイルをブラウザで開けばそのまま動くため、変更の結果をすぐ確認できる。
- 利用者ごとの状態（閲覧済みの絶景スポット、選択中のテーマ）はブラウザの localStorage に保存する。サーバーに利用者データを持たないため、個人情報の管理も発生しない。
- 絶景スポットの情報は `spots.json` に置き、コードから分離する。内容の追加・修正にプログラミングの知識を要さない。
