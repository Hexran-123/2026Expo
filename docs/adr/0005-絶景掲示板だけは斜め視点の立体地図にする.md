# 絶景掲示板だけは斜め視点の立体地図にする

[ADR-0001](./0001-地図はタイルを使わず自作イラストとする.md) は、車窓絶景ナビの地図を平面のイラストにすると決めた。理由は「車内で一瞬見るには読み取れない」——電車に乗っている人が、揺れる車内でちらっと見て場所を把握できることが最優先だったため。

絶景掲示板（[docs/絶景掲示板_設計メモ.md](../絶景掲示板_設計メモ.md)）は、この前提が成り立たない別の画面である。旅行前に PC でじっくり眺める、パソコン専用の画面として設計している。一瞬で読み取れる必要はなく、むしろ「銚子の地形がどうなっているか」を眺めて楽しんでもらうことが目的に近い。

そこで、絶景掲示板の地図だけは CSS の 3D 変形を使い、ドラッグで回転・傾きを変えられる斜め視点にすることにした。地形の色分け（設計書 5.2 と同じ配色・考え方）はそのまま引き継ぐため、「実データを骨格にする」という ADR-0001 の芯までは変えていない。変えたのは見せ方（平面か立体か）だけである。

比較検討は Claude Artifact 上のプロトタイプ（v1〜v4）と Playwright での実際の操作確認を重ねて行った。線路の高さ表現だけで 5 案（階段状／実測を軽く均した坂／しっかり均した坂／駅の実測標高だけを通る曲線／平坦＋支柱）を作って比べ、駅を通る曲線（Catmull-Romスプライン）を採用した。誇張度も ×2.4 を試したうえで「あらゆるものが浮いて見える」という指摘を受け ×1.2 に落ち着かせた。経緯は設計メモ 4 章に記録している。

## Consequences

- 地図の実装を 2 つ抱えることになる。車窓絶景ナビ（SVG・平面）と絶景掲示板（CSS 3D・斜め視点）は別のコードで、片方を直してももう片方には反映されない。
- 絶景掲示板はモバイル非対応（画面が狭いときは地図を出さず案内ページのみ）と決めているため、ADR-0001 が捨てた「タイル地図」的な操作感（ドラッグ・回転・ズーム）を、ここでは PC 専用という限定つきで復活させたことになる。
- 標高の誇張（×1.2）は見た目の調整であり、実測値そのものではない。数値を読ませる画面ではないため許容している。
- **ピンだけは3Dの中に置かない。** CSS の3D変形には本物のZバッファが無く、地形の板（0〜45mの6枚）とピンの前後関係が正しく解かれない。3Dの中に置いていたあいだは、地形のいちばん上の板（z=54）より高く持ち上げないと低地のピンが板の裏に回って消えるため、底上げ +80 を入れていた。地形全体の高さが54しかないので、これは「地形の1.5倍の高さに浮かせる」ことを意味し、実際に「すごく浮いている」という指摘を受けた（2026-08-19）。

  そこで、3D空間の座標を JavaScript で画面座標に投影し（`projectToScreen`）、地図の上に重ねた平らな層にピンを並べる形に変えた。前後関係の問題そのものが消えるので、ピンは実測標高そのまま——つまり地面の高さ——に置ける。尻尾の先がその場所の地面にちょうど触れる。

  投影はブラウザ自身が解いた3D位置と 0.05px 以内で一致することを確認した（移動・回転・傾き・拡大・窓の大きさ変更のすべてで）。同じ座標を持つ外川駅のピンと外川駅の駅名マークが、画面上で 1px 差に収まることも確かめている。

- 投影の式は `.map-wrap` の `perspective` と `.camera-rig` の変形に依存する。**CSS 側のこれらを変えたら `projectToScreen` と `PERSPECTIVE` 定数も直すこと。** 同じ変換を2か所に持つことになるのは、この方式の代償である。
- 地形の段彩が45m以上をひとまとめにしている都合で、ピンの高さは45mで頭打ちにしている（それを超える愛宕山などで、描かれている地面より高く浮くのを避けるため）。
- 絶景スポットの座標は [data/choshi/board-spots.json](../../data/choshi/board-spots.json) を出典つきで持つ。車窓絶景ナビの `spots.json` とはファイルが分かれているため、同じ場所（例: キャベツ畑）でも座標がずれないよう、書き換えるときは両方を確認する。
