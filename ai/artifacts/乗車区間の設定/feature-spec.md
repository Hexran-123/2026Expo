# 機能規格書

## Metadata

- 機能：乗車区間の設定（乗車駅・降車駅の事前設定）
- 負責人：（未定）
- 状態：已實作
- 風険レベル：中（初回起動フローを追加し、既存の「利用者に申告させない」設計思想の一部に例外を設けるため）

## 問題

乗車前モードは、路線全体・全スポットを一様に見せる設計になっている。しかし銚子電鉄を始点（銚子）から終点（外川）まで乗り通す利用者は少なく、多くは区間利用である。区間を知らないアプリは、利用者が実際には通らない区間のスポット情報（見どころリスト・接近通知）まで一様に出してしまい、本当に必要な情報が埋もれる。

また、発車待ちの見どころリストは「乗る向きがまだ決まっていない」という前提のもと、上り・下り両方の車窓側を常に併記している（例:「上り 左／下り 右」）。区間（＝方向）が事前にわかれば、見るべき片側だけを示せるのに、常に冗長な表記になっている。

## 使用者

銚子電鉄に乗る、この作品の利用者全員。区間利用者を主な対象とするが、始発から終点まで乗る利用者も同じ導線でカバーする（乗車駅＝銚子、降車駅＝外川を選ぶだけでよい）。

## 目標

- アプリを開いた最初に、乗車駅・降車駅を必ず選ばせ、その区間を記憶する（スキップなし）。
- 区間から方向（上り/下り）を自動的に決め、利用者に別途方向を選ばせない。
- 発車待ちの時刻表・見どころリストを、設定した区間・方向に応じて絞り込み・簡略化する。
- 車上モード中の接近通知を、設定区間内のスポットだけに制限する。
- 設定はあとから変更できる。
- 実際のGPS判定（乗車駅・方向）が設定と食い違ったら、そのトリップ中に一度だけ気づかせ、設定を直すか確認する。

## 非目標

- モード自動判定（乗車前／発車待ち／車上／降車後の切り替え）のロジック自体は変えない。GPSに基づく自動判定は今まで通り（設計書3.2）。
- 設定した区間と実際の位置が食い違っても、GPSの判定を上書き・矯正しない。あくまで一度だけ通知し、設定を更新するかを尋ねるだけで、モード判定・現在位置表示には介入しない。
- 地図のズーム・ハイライト表示を区間に応じて変えることはしない（今回のスコープ外。将来検討）。
- 通過判定・成因カードの自動表示・旅の記録への記録（設計書6・7章）は、区間の内外にかかわらず今まで通り動く。絞るのは「事前の接近通知」だけ。
- 天気×地図の統合（別Epicで決定済みの仕組み）には影響しない。

## 使用者旅程

```text
身為 これから銚子電鉄に乗る利用者
我想要 乗る駅・降りる駅を選ぶだけで、自分の区間に合った時刻表・見どころ・通知を受け取りたい
以便 始点から終点までの全区間の情報に埋もれず、自分に関係あることだけに集中できる
```

1. 利用者がアプリ（URL）を開く。保存された区間設定が無い。
2. 地図画面より先に、乗る駅・降りる駅を選ぶ画面が出る。両方選ぶまで先に進めない。
3. 選ぶと方向が自動的に決まり、地図画面（乗車前モード）に進む。地図のどこかに選んだ区間（例:「銚子→外川」）が小さく表示され、押すといつでも選び直せる。
4. 発車待ちに入ると、設定した乗車駅・方向に応じた時刻表と、区間内の見どころ（車窓側は片方だけ）が出る。
5. 車上モードでは、区間内のスポットにだけ接近通知が出る。区間外のスポットを通過しても、通過自体は記録され成因カードも出るが、事前の接近通知はない。
6. 実際にGPSが検出した乗車駅・方向が設定と違う場合、そのトリップ中に一度だけ「〇〇からお乗りのようです。設定を直しますか？」のような確認が出る。「直す」を選べば以後はその設定が使われ、以後の区間判定・通知もそれに従う。「このまま」を選べば、そのトリップ中は元の設定のまま動作する。
7. 降車後（旅の記録）に着いたら、食い違い確認済みフラグはリセットされる。次のトリップでまた食い違いがあれば、再度一度だけ知らされる。

## 機能要件

- WHEN 保存済みの区間設定が無い状態でアプリを開いた THE SYSTEM SHALL 地図画面より先に、乗る駅・降りる駅を選ぶ画面を表示し、両方選択されるまで地図へ進めない。
- WHEN 利用者が乗る駅・降りる駅を選んだ THE SYSTEM SHALL 選んだ2駅の路線上の順序（distanceAlongの大小）から方向（上り/下り）を自動的に決定し、利用者に別途方向を選ばせない。
- WHEN 利用者が乗る駅と降りる駅に同じ駅を選ぼうとした THE SYSTEM SHALL 選択を確定させない（決定ボタンを無効にする、または別の駅を促す）。
- WHEN 区間設定が確定した THE SYSTEM SHALL 乗車駅・降車駅・方向を、設定した日付とともにブラウザに保存する。
- WHEN 保存された区間設定の日付が今日と同じ状態でアプリを開いた THE SYSTEM SHALL 選択画面を出さず、その区間をそのまま引き継ぐ（往復での開き直しや、トンネル・圏外によるページ再読み込みで、そのつど聞かない）。
- WHEN 保存された区間設定の日付が今日と異なる状態でアプリを開いた THE SYSTEM SHALL 未設定として扱い選択画面を表示する。ただし前回の乗車駅・降車駅を初期値として入れておき、同じ区間なら「決定」の一手で済むようにする。
  - 理由：区間は「その日の乗車」の設定であって恒久の設定ではない。日付を見ずに残していたころは、翌日ちがう区間に乗るのにアプリを開いても黙って前回の範囲で絞り込んでいた（時刻表は前回の向きだけ、見どころも通知も前回の範囲だけ）。しかも区間は畳まれた上の帯の中にしか出ていないため、気づく手がかりが無かった。
- WHEN 利用者が地図画面から設定の変更を選んだ THE SYSTEM SHALL 導入フローと同じ選択画面を再度開き、選び直させる。
- WHEN 発車待ちに入った THE SYSTEM SHALL 設定した乗車駅・方向をもとに次発の時刻表を表示する（実際にいる駅ではなく設定を優先する場合の扱いはUS7の食い違い確認に従う）。
- WHEN 発車待ちの見どころリストを組み立てる THE SYSTEM SHALL 設定区間（乗車駅のdistanceAlong〜降車駅のdistanceAlongの範囲）内のスポットだけを対象にし、車窓側は設定方向で決まった片側だけを表示する。
- WHEN 車上モード中に絶景スポットへ接近した THE SYSTEM SHALL そのスポットが設定区間内にある場合のみ接近通知を出す。区間外のスポットは通過判定・成因カードの自動表示・旅の記録への記録は今まで通り行うが、接近通知だけは出さない。
- WHEN 車上モードで実際にGPSから検出された乗車駅または方向が設定と異なる THE SYSTEM SHALL そのトリップ中に一度だけ確認を表示し、「直す」（設定を更新し以後の区間判定に反映する）と「このまま」（設定を変えずそのトリップを続ける）を選ばせる。
- WHEN 降車後（旅の記録）に到達した THE SYSTEM SHALL 食い違い確認済みフラグをリセットし、次のトリップで再び食い違いがあれば改めて一度だけ知らせる。

## 資料與 API

- 輸入：区間設定画面での乗車駅名・降車駅名の選択（route.jsonの駅一覧から選ぶ）。
- 輸出：乗車駅・降車駅・方向をブラウザ（localStorage）に保存。既存のテーマ絞り込み設定と同じ保存パターンを踏襲する。
- 検証：乗車駅と降車駅が同一でないこと。両方がroute.jsonに存在する駅名であること。
- 錯誤：保存された設定が壊れている・存在しない駅名を指している場合は、未設定として扱い、区間設定画面を再度出す。
- 新しい外部API通信は増えない（既存のroute.json・schedule.jsonの範囲で完結する）。

## 安全性與隱私

- 身分認證：なし（既存どおり）。
- 権限：なし。
- 機密資料：保存するのは「駅名2つ・方向」のみ。個人を特定する情報ではなく、localStorageのみに留まりサーバー送信はない（ADR-0002、フレームワーク・サーバーを持たない構成を維持）。
- 濫用情境：なし（外部に影響する操作がないため）。

## 驗收標準

- 保存済みの区間設定が無い状態でアプリを開くと、地図より先に区間設定画面が出て、両方選ぶまで地図に進めない。
- 区間を選ぶと、方向が自動的に決まり、別途方向を選ぶ操作は存在しない。
- 同じ駅を乗車駅・降車駅の両方に選ぶことはできない。
- 設定は次回起動時も保持される。
- 地図画面から、いつでも設定を変更できる。
- 発車待ちの時刻表・見どころリストが、設定した区間・方向に応じたものになる（見どころの車窓側は片方だけ表示される）。
- 車上モードの接近通知が、設定区間内のスポットだけで発生する（区間外は通過判定・成因カード・旅の記録は今まで通り）。
- 実際のGPS判定が設定と食い違うと、トリップ中に一度だけ確認が出る。「直す」を選べば設定が更新される。「このまま」を選べばそのトリップ中は元の設定が続く。
- 降車後に到達すると、食い違い確認済みフラグがリセットされる。
